02

Install for your macOS.

Start with a backup of your working EFI and a tested bootable recovery copy. Mount the EFI partition you actually boot from; this driver does not replace your full OpenCore configuration.

  1. Download AirPortRTW-1.1.0.zip and extract it once. Use the packaged release, not the Source code archives.
  2. Copy the complete AirPortRTW.kext bundle to EFI/OC/Kexts/.
  3. In EFI/OC/config.plist, enable AirPortRTW.kext under Kernel → Add. If you use an OC Snapshot tool, review its changes and avoid duplicate entries.
  4. Disable the older Feixiao rtw88.kext and duplicate AirPortRTW builds. Then follow the matching macOS requirements below before rebooting.
EFIOCKextsAirPortRTW.kext

Ventura: use the system stack

Keep the system com.apple.iokit.IOSkywalkFamily enabled. Do not add a Kernel → Block entry for it, and do not inject the restored IOSkywalkFamily.kext or IO80211FamilyLegacy.kext from the newer-macOS setup.

Lilu and AMFIPass may be required elsewhere in your EFI, but are not part of this Ventura-specific AirPort-RTW dependency chain.

Sonoma, Sequoia & Tahoe: restore compatible Wi-Fi components

AirPortRTW alone is not enough. Use legacy Wi-Fi payloads compatible with your exact macOS release; extract the actual kext bundles from their archives.

Enable the dependencies in this Kernel → Add order:

  1. Lilu.kext
  2. AMFIPass.kext
  3. IOSkywalkFamily.kext
  4. IO80211FamilyLegacy.kext
  5. AirPortRTW.kext

Block the system com.apple.iokit.IOSkywalkFamily with Strategy Exclude, restricted to the Darwin versions that use the replacement. SecureBootModel must be compatible with the restored stack. These settings depend on your macOS version: follow the project guide rather than copying limits from an unrelated EFI.

IO80211ElCap and corecaptureElCap are not required for this setup.

Already running AirPort-RTW?

For a working setup on the same macOS version, replace AirPortRTW.kext and keep your compatible dependencies. Recheck the complete stack when upgrading macOS.

03

Reboot. Connect. Check.

Restart through the OpenCore EFI you edited. Open the macOS Wi-Fi menu, turn Wi-Fi on, select your WPA2 network and enter its password. No separate connection utility is needed.

Check the attached driver build in Terminal:

Terminal
ioreg -r -c AirPortRTW -l | grep DriverBuild

For this release, the result should include 1.1.0. No output? Check the PCI ID, your enabled OpenCore entry, duplicate drivers and the Wi-Fi components required for your macOS version.

Open a website to test internet access. Also test Wi-Fi off/on and sleep/wake: a successful boot alone does not confirm full compatibility.

04

Move between access points.

Automatic roaming is on by default in 1.1.0. The driver checks nearby compatible access points on the same network and can switch to a better connection. Signal checks and a cooldown help avoid unnecessary changes.

Supported 802.11k and 802.11v features help discover access points and consider router suggestions. Some functions remain experimental; a router advertising 11k/v does not guarantee every optional feature. 802.11r is not implemented.

How to turn automatic roaming off

Append -rtwnoautoroam to your existing boot-args in config.plist under NVRAM → Add → 7C436110-AB2A-4BBB-A880-FE41995C9F82. Keep all existing arguments and restart. Remove this argument and restart to enable roaming again.

05

Know the current limits.

Packet drops under heavy load

Heavy downloads and speed tests can cause packet drops. This is unresolved in 1.1.0; investigation is planned for 1.1.1.

  • Reconnect after sleep can be slow. Deep sleep and hibernation are not fully reliable on all systems.
  • WPA2-Enterprise / 802.1X is experimental and has not been verified on physical hardware. WPA3 and PMF are unsupported.
  • AirDrop and full Continuity support are not included in this release.
  • RTL8814AE still needs physical hardware testing.
